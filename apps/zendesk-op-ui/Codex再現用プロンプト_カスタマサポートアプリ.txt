以下の要件で、React + Vite のシングルページアプリを再現してください。

【実装方針】
- 1ファイル中心で実装（主要UI/ロジックは `src/App.jsx` に集約）。
- 日本語UI。
- OP（コールセンター）向け。迷わない導線を最優先。
- モバイル幅UI（約320px）をPCブラウザで表示する設計。
- 既存コードがある場合は見た目と文言の整合を優先し、不要な重複文言を削減する。

【技術要件】
- React 18
- Vite 5
- 依存は `react`, `react-dom` のみ（必要最小）

【最終UI仕様（必須）】
1) ヘッダー
- タイトル: `カスタマサポートアプリ`

2) STEP1
- 見出し: `STEP 1` + `検索`
- 検索対象: 電話/メール/顧客ID/氏名
- `新規登録` 導線を配置

3) STEP2
- 見出し: `STEP 2` + `登録情報`
- 顧客サマリ表示（氏名、ID、電話、メール、登録住所など）
- 鉛筆アイコンから登録情報編集シートを開く

4) STEP3（重要）
- 見出し: `STEP 3` + `操作対象`
- 対象定期を選ぶUI
- このエリアには `発送待ち` など注文ステータスタグを表示しない
- 停止中の定期はトグルで展開可能

5) タブ
- タブ名は `注文詳細/変更` と `注文履歴`

6) 注文詳細/変更タブ（最重要）
- `定期ステータス` を明示（`継続中` / `停止中`）
- ステータス近くにボタン:
  - `定期停止`（停止中は `定期再開`）
  - `キャンセル処理`
- 次回注文カードに表示:
  - 注文番号（EP形式）と注文ID
  - 子注文明細（複数行）
  - `ポイント利用`（編集可）
  - 必要時のみ `クーポン`、`送料`
  - `今回の請求合計` は明細の最下部に配置（上部カードには置かない）

7) 明細の個別編集
- 商品行ごとに鉛筆で編集シートを開く
- 数量・単価を編集可能
- `single_add` 行は削除可能
- `ポイント利用` も個別編集シートで編集可能

8) 注文履歴タブ
- `単品注文` セクションと `定期注文履歴` セクションを分離表示
- 単品注文行に `編集` 導線を配置
- 単品注文編集シートで以下を編集可能:
  - 商品名、サイズ、数量、発送日、時間帯、金額、ステータス、メモ
  - `この単品注文をキャンセル` ボタン

9) 定期なし顧客対応
- `定期便なし` カードを表示
- `単品テンプレで別送作成` 導線を配置
- 単品テンプレは:
  - `単品別送`
  - `お詫び別送`
  - `差し替え発送`

10) 低頻度業務
- 未注文顧客の新規登録フロー（2ステップ）を実装:
  - 顧客情報
  - 初回注文情報

【データ要件（最低限）】
- 顧客、定期、子注文、注文履歴のモックデータを持つ
- 子注文構造:
  - `lineItems[]`（type: `subscription` / `single_add`）
  - `pointsUsed`, `couponDiscount`, `shippingFee`, `totalAmount`
- 合計計算:
  - `totalAmount = lineItems合計 - pointsUsed - couponDiscount + shippingFee`
  - 下限0

【文言整合（必須）】
- `STEP 3` は `操作対象`
- タブは `注文詳細/変更`
- `今回の請求合計` は明細最下部
- 重複説明文を極力排除し、OPの判断負荷を下げる

【受け入れチェック（実装後に自己検証）】
- STEP3に注文ステータスタグが出ていない
- 注文詳細/変更タブに定期停止/再開とキャンセル処理がある
- 明細行とポイント利用が個別編集できる
- 単品注文を履歴から編集・キャンセルできる
- 定期なし顧客でも単品作成フローが成立する

【出力形式】
- 変更したファイル一覧
- 実装の要点（短く）
- 起動手順
- 既知制約
