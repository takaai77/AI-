# Chatwork AI返信下書きサポート Chrome拡張

Chatwork Web版のメッセージ入力欄の近くに「AI返信」ボタンを表示し、
AIが返信の下書きを作成するChrome拡張機能です。

**重要: この拡張機能は送信を自動で行いません。下書きの作成のみを行います。**
送信ボタンを押すのは必ず人間です。

## 概要

- Chatwork Web版でのみ動作
- LINEのAI返信のような軽量UIで下書きを提案
- GCP Application Integration → Gemini Flash API で文面を生成
- 入力欄に「挿入」するだけ。送信は行わない
- 個人情報の簡易マスク機能付き
- カスタムプロンプトで自社ルール・文体を指定可能
- 返信テンプレートで定型的な返信をワンクリックで生成

## セットアップ手順

### 前提条件

- Google Chrome ブラウザ（バージョン 116 以降推奨）
- GCP プロジェクト（Application Integration + API Gateway）
- Gemini API キー（GCP側で設定。拡張内には保持しない）

### 1. リポジトリの取得

```bash
git clone <このリポジトリのURL>
```

### 2. Chromeへの読み込み

1. Chromeで `chrome://extensions` を開く
2. 右上の **「デベロッパーモード」** をONにする
3. **「パッケージ化されていない拡張機能を読み込む」** をクリック
4. `chatwork-ai-draft/` フォルダを選択する
5. 拡張機能が読み込まれ、ツールバーにアイコンが表示される

### 3. GCP側の構築

詳細は [GCP_ARCHITECTURE.md](./GCP_ARCHITECTURE.md) を参照してください。

概要:
1. GCP プロジェクトを作成
2. Gemini API を有効化
3. Application Integration でフローを作成
4. API Gateway を設定
5. API Gateway 用の制限付きAPIキーを発行

#### リクエスト形式（この拡張から送られるJSON）

```json
{
  "roomName": "配送相談",
  "threadContext": [
    { "speaker": "相手", "text": "発送日は変更できますか？" },
    { "speaker": "自分", "text": "確認いたします。" }
  ],
  "intent": "丁寧に短く返信したい",
  "tone": "polite",
  "retryMode": false,
  "customPrompt": "です・ます調で統一してください。",
  "templateName": "確認・承知"
}
```

> `customPrompt` と `templateName` はオプションフィールドです。
> 設定画面でカスタムプロンプトが設定されている場合、
> またはテンプレートが選択された場合にのみ含まれます。

#### レスポンス形式（GCPが返すべきJSON）

```json
{
  "ok": true,
  "draft": "お問い合わせありがとうございます。発送日変更について確認のうえご案内いたします。",
  "toneLabel": "丁寧",
  "notes": "確定情報がないため断定を避けています。"
}
```

#### tone の値

| 値 | 意味 |
|---|---|
| `neutral` | 通常 |
| `polite` | 丁寧 |
| `short` | 短い |

### 4. 拡張機能の設定（options画面）

1. Chromeの拡張機能アイコンをクリック → 設定画面が開く
2. **エンドポイントURL** に GCP API Gateway の URL を入力
3. **APIキー** に API Gateway 用の制限付きキーを入力（任意。config.js にデフォルト設定可能）
4. **取得メッセージ件数** を設定（推奨: 3〜5件）
5. **カスタムプロンプト** に自社ルールや文体指定を入力（任意）
6. **返信テンプレート** を必要に応じて追加・管理
7. 「設定を保存」をクリック

### 5. 100人への配布（管理者向け）

1. `config.js` の `DEFAULT_ENDPOINT_URL` に API Gateway URL を設定
2. `config.js` の `DEFAULT_API_KEY` に API Gateway 用キーを設定
3. 拡張をパッケージ化して配布（Chrome管理コンソール推奨）

これにより社員は設定なしで使い始められます。

## Chatwork上での使い方

1. Chatwork Web版 (`https://www.chatwork.com/`) を開く
2. チャットルームを選択する
3. メッセージ入力欄の近くに **「✨ AI返信」ボタン** が表示される
4. ボタンをクリックするとAIカードが開く
5. 「どう返信したいですか？」にざっくり意図を入力して「返信を提案」（Enterで送信可能）
6. 下書きプレビューが表示される
7. 必要に応じてトーンを変更（🎩丁寧に / ✂️短く）
8. **🔄再生成** で別の表現を試す
9. **📥入力欄に挿入** をクリックすると、Chatworkの入力欄にテキストが入る
10. **内容を確認し、自分で送信ボタンを押す**

## テンプレート機能

### プリセットテンプレート（8種類）

| アイコン | テンプレート名 | 用途 |
|---|---|---|
| 🙏 | お礼の返信 | 感謝を丁寧に伝える |
| ✅ | 確認・承知 | 承知した旨を返信 |
| 🙇 | やんわりお断り | 相手を傷つけずに断る |
| ❓ | 質問・確認依頼 | 不明点を質問 |
| 📅 | 日程調整 | 日程の候補提案・調整 |
| 📊 | 進捗報告 | 作業進捗の簡潔な報告 |
| 💦 | お詫び | 遅延やミスのお詫び |
| 📝 | 依頼・お願い | タスクや対応の依頼 |

### カスタムテンプレートの追加

設定画面の「返信テンプレート管理」セクションから、
自分専用のテンプレートを追加・削除できます。

### カスタムプロンプト

設定画面の「カスタムプロンプト」欄に、AIへの追加指示を設定できます。

例:
- 「返信はです・ます調で統一してください」
- 「社名は「株式会社サンプル」です」
- 「敬語レベルを高めにしてください」

この内容は `customPrompt` フィールドとして GCP に送られます。
GCP の Application Integration 内で Gemini API のシステムプロンプトに結合してください。

## セキュリティ方針

詳細は [SECURITY.md](./SECURITY.md) を参照してください。

### 要約

| 方針 | 内容 |
|---|---|
| **APIキー非保持** | Gemini APIキーはGCP側のみで管理。拡張が持つのはAPI Gateway用の制限付きキーのみ |
| **データ最小化** | 直近3件のメッセージのみ送信。個人情報は簡易マスク |
| **保存最小化** | localStorage不使用。一時データはメモリ/session storage |
| **ログ最小化** | 会話本文・下書き本文をconsole.logに出力しない |
| **権限最小化** | Chatworkドメインのみに制限。`<all_urls>` 不使用 |
| **送信禁止** | 送信ボタンの自動操作は一切行わない |
| **XSS防止** | innerHTML不使用。textContentベースで表示 |

## 制限事項

- **DOMセレクタ**: ChatworkのDOM構造が変更されると動作しなくなる可能性がある。
  `lib/dom-selectors.js` と `TODO_SELECTORS.md` を参照して更新してください。
- **個人情報マスク**: 完全ではない。正規表現ベースの簡易マスクのため、
  すべての個人情報を検出できるわけではない。
- **SPA遷移**: Chatworkはシングルページアプリケーションのため、
  ルーム切り替え時にUIの再初期化が必要。MutationObserverで対応しているが、
  稀にボタンが消える場合がある（ページリロードで復帰）。
- **テンプレートのエクスポート**: 現時点ではテンプレートのインポート/エクスポート機能はない。

## 本番運用での注意点

1. **HTTPS必須**: エンドポイントURLは必ず HTTPS を使用すること。
2. **Gemini API利用規約**: 業務データをAIに送る場合、
   Gemini API の利用規約を確認すること。
   有料プランではデータがモデル学習に使用されない。
3. **アイコン**: 現在のアイコンはプレースホルダー。
   本番では適切なアイコンに差し替えること。
4. **カスタムプロンプトの運用**: 全社で統一するプロンプトがある場合、
   GCP 側のシステムプロンプトに直接設定する方が管理しやすい。
   拡張側のカスタムプロンプトは個人の微調整用途を想定。
