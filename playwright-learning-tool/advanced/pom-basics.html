Month 2: テスト設計

🏗️ Page Object Model (POM) の基礎

保守性の高いテストコードを書くための設計パターン

🤔 なぜPOMが必要？

テストコードが増えてくると、以下の問題が発生します：

  • 同じセレクタが複数のテストに散在
  • UIが変更されると、多くのテストを修正する必要がある
  • テストコードが読みにくい

Page Object Modelは、ページごとにクラスを作成し、セレクタとアクションをカプセル化することで、これらの問題を解決します。

📊 Before / After 比較

❌ POMなし（悪い例）

// セレクタが散在 test('ログインできる', async ({ page }) => { await page.goto('/login'); await page.fill('#email', 'test@test.com'); await page.fill('#password', 'pass123'); await page.click('button[type="submit"]'); }); test('ログイン失敗', async ({ page }) => { await page.goto('/login'); await page.fill('#email', 'wrong@test.com'); await page.fill('#password', 'wrong'); await page.click('button[type="submit"]'); });

✅ POMあり（良い例）

// 読みやすく保守しやすい test('ログインできる', async ({ page }) => { const loginPage = new LoginPage(page); await loginPage.goto(); await loginPage.login( 'test@test.com', 'pass123' ); }); test('ログイン失敗', async ({ page }) => { const loginPage = new LoginPage(page); await loginPage.goto(); await loginPage.login( 'wrong@test.com', 'wrong' ); });

🔧 実装方法

1. BasePage（共通機能）

// pages/BasePage.js class BasePage { constructor(page) { this.page = page; this.baseURL = process.env.BASE_URL || 'https://example.com'; } // 共通: ページ遷移 async navigate(path) { await this.page.goto(`${this.baseURL}${path}`); } // 共通: タイトル取得 async getTitle() { return await this.page.title(); } // 共通: ローディング待機 async waitForLoading() { await this.page.waitForLoadState('networkidle'); } // 共通: スクリーンショット async takeScreenshot(name) { await this.page.screenshot({ path: `screenshots/${name}.png`, fullPage: true }); } } module.exports = { BasePage };

2. LoginPage（ログインページ）

// pages/LoginPage.js const { BasePage } = require('./BasePage'); class LoginPage extends BasePage { constructor(page) { super(page); // セレクタを1箇所に集約 this.selectors = { emailInput: '[data-testid="email-input"]', passwordInput: '[data-testid="password-input"]', submitButton: '[data-testid="login-button"]', errorMessage: '[data-testid="error-message"]', forgotPassword: '[data-testid="forgot-password-link"]' }; } // ログインページに移動 async goto() { await this.navigate('/login'); await this.waitForLoading(); } // メールアドレスを入力 async fillEmail(email) { await this.page.fill(this.selectors.emailInput, email); } // パスワードを入力 async fillPassword(password) { await this.page.fill(this.selectors.passwordInput, password); } // ログインボタンをクリック async clickSubmit() { await this.page.click(this.selectors.submitButton); } // ログイン処理（よく使う操作をまとめる） async login(email, password) { await this.fillEmail(email); await this.fillPassword(password); await this.clickSubmit(); await this.waitForLoading(); } // エラーメッセージを取得 async getErrorMessage() { const element = this.page.locator(this.selectors.errorMessage); if (await element.isVisible()) { return await element.textContent(); } return null; } // ログイン成功したかチェック async isLoggedIn() { return this.page.url().includes('/dashboard'); } } module.exports = { LoginPage };

3. テストコード

// tests/login.spec.js const { test, expect } = require('@playwright/test'); const { LoginPage } = require('../pages/LoginPage'); test.describe('ログイン機能', () => { let loginPage; test.beforeEach(async ({ page }) => { loginPage = new LoginPage(page); await loginPage.goto(); }); test('正しい認証情報でログインできる', async () => { await loginPage.login('user@example.com', 'password123'); expect(await loginPage.isLoggedIn()).toBe(true); }); test('間違ったパスワードでエラーが表示される', async () => { await loginPage.login('user@example.com', 'wrongpass'); const errorMsg = await loginPage.getErrorMessage(); expect(errorMsg).toContain('パスワードが正しくありません'); }); test('空のフィールドでバリデーションエラー', async () => { await loginPage.clickSubmit(); const errorMsg = await loginPage.getErrorMessage(); expect(errorMsg).toContain('入力してください'); }); });

💡 ベストプラクティス

1. data-testid を使う

CSSクラスやIDは変更されやすいため、テスト専用の data-testid 属性を使うことで、UIの変更に強いテストを書けます。

2. アクションは動詞で命名

login(), addToCart(), submitForm() のように、何をするかが明確な名前を付けましょう。

3. 状態確認は is/has/get で命名

isLoggedIn(), hasError(), getTotal() のように、結果を返すメソッドは明確に区別しましょう。

4. 待機処理をメソッド内に含める

アクションメソッド内で適切な待機を行うことで、テストコードがシンプルになります。
